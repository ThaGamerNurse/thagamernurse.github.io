Gaston Quant

A trading agent, and three layers that decide what it can do.

A desktop app over a local server, running a trading cycle against a live brokerage account. Most of the build went into the safety side.

LAYER 1

The broker refuses

Eight of nine accounts reject orders server-side. The one tradeable account is cash-only, so leverage is unavailable rather than merely disallowed, and the option level does not permit spreads.

LAYER 2

The code refuses

A sell requires a token minted by a human, valid 120 seconds, bound to a hash of that exact order. Nothing on an agent path can mint one, so the trading loop is refused the same way a stranger would be.

LAYER 3

The rules refuse

A strategy file can tune entry and sizing. It is rejected outright if it so much as names a safety rule, so installing a strategy can never mean disabling a safeguard.

How it's built

I never learned to program.

So I built a way of working with AI instead, and these came out of it. Four parts of it do most of the work.

State that survives

One document every session reads before it starts and writes back to the moment it learns something. Nothing begins cold, and a correction never lives only in a chat log.

Cheapest model that can do it

Mechanical work goes to a small fast model, judgment goes to the strongest one, and anything touching money, health data or a deployment always goes up.

Someone tries to knock it down

Findings get handed to separate agents told to disprove them. If most succeed, the finding is thrown out. That is why twelve audit rounds produced 53 defects that were real.

Corrections get a check

A correction goes into the rules file the same day, with an automated test that fails if the old mistake ever comes back.

I wrote the whole thing up, including the failures that produced each rule and the one that convinced me it was all necessary.
